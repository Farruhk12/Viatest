# Техническое задание: информационный сайт тестов на беременность

## 1. Цель проекта

Создать современный, доверительный и максимально простой информационный сайт о тестах на беременность.

Основные задачи сайта:

1. Понятно объяснить пользователю, какой тест выбрать.
2. Показать, когда и как правильно проводить тест.
3. Помочь корректно интерпретировать результат.
4. Ответить на основные вопросы, возникающие до и после тестирования.
5. Подвести пользователя к покупке.
6. По кнопке **«Купить»** перенаправлять пользователя на соответствующую внешнюю страницу товара.
7. Использовать изображения, логотип, упаковки и инструкции, находящиеся локально в папке проекта.

> Сайт является информационным ресурсом и витриной. Корзина, оформление заказа и приём платежей на самом сайте не требуются.

---

# 2. Основная концепция

Сайт должен быть построен не как обычный каталог товаров, а вокруг пользовательского сценария:

> **«Когда делать тест → какой тест выбрать → как правильно использовать → как понять результат → что делать дальше → купить тест».**

Главный принцип UX:

- минимум медицинского и технического перегруза;
- максимум понятных визуальных подсказок;
- спокойный и деликатный дизайн;
- mobile-first;
- важная информация доступна за 1–2 действия;
- кнопка **«Купить»** присутствует во всех ключевых точках пользовательского пути.

---

# 3. Работа с файлами проекта

Все медиафайлы должны браться из папки проекта.

Не использовать случайные изображения из интернета, если нужный материал уже существует локально.

Предпочтительная структура:

```text
/project
  /assets
    /logo
    /products
    /instructions
    /results
    /icons
    /backgrounds
  index.html / src/
  README.md
  WEBSITE_SPEC.md
```

Допускается другая структура, если существующий проект уже организован иначе.

При реализации необходимо:

- автоматически найти основной логотип;
- найти фотографии упаковок тестов;
- найти изображения инструкции;
- использовать локальные изображения результатов теста, если они имеются;
- сохранять оригинальное соотношение сторон изображений;
- не растягивать упаковки;
- использовать WebP/AVIF там, где это возможно без потери качества;
- добавлять `alt` для значимых изображений.

# 4. Цветовая палитра и визуальный стиль

Фиксированную цветовую палитру заранее не задавать.

После добавления проекта необходимо определить визуальную систему по логотипу и упаковке продукта.

## Правило формирования палитры

Из логотипа выбрать:

- `Primary` — основной фирменный цвет;
- `Secondary` — дополнительный фирменный цвет;
- `Accent` — цвет CTA и важных элементов;
- `Background` — очень светлый нейтральный/фирменный фон;
- `Surface` — фон карточек;
- `Text Primary` — основной тёмный текст;
- `Text Secondary` — вторичный текст;
- `Success`;
- `Warning`;
- `Error`.

Не использовать чрезмерно яркую «аптечную» стилистику.

Визуальный характер сайта:

- современный;
- чистый;
- мягкий;
- медицински аккуратный;
- женственный без клише;
- много воздуха;
- скруглённые карточки;
- качественная типографика;
- крупные фотографии продукта;
- понятные пиктограммы;
- лёгкие анимации;
- никаких агрессивных баннеров.

# 8. Блок «Когда делать тест?»

Создать интерактивный информационный блок.

Минимальный вариант:

- объяснение, когда обычно используется тест;
- важность соблюдения инструкции конкретного продукта;
- ссылка на официальную инструкцию продукта.

Расширенный вариант:

## Калькулятор «Когда сделать тест»

Поля:

- первый день последней менструации;
- средняя продолжительность цикла;
- опционально — предполагаемая дата овуляции.

Результат:

- предполагаемая дата следующей менструации;
- информационная подсказка о времени тестирования;
- кнопка **«Купить тест»**.

### Медицинское ограничение

Не использовать калькулятор как диагностический инструмент.

Добавить текст:

> Расчёт носит информационный характер. Ориентируйтесь на инструкцию конкретного теста и рекомендации медицинского специалиста.

# 11. Пошаговая инструкция

Это один из главных информационных блоков сайта.

Формат:

### Шаг 1
Изображение + короткое действие.

### Шаг 2
Изображение + короткое действие.

### Шаг 3
Изображение + короткое действие.

### Шаг 4
Изображение + когда оценивать результат.

Количество шагов определяется официальной инструкцией конкретного продукта.

## Важно

Текст инструкции нельзя придумывать.

Источник приоритета:

1. инструкция производителя в папке проекта;
2. информация на упаковке;
3. подтверждённые материалы бренда.

Если данных недостаточно — оставить блок как TODO, а не создавать медицинские параметры самостоятельно.

# 14. «Слабая вторая полоска»

Отдельный информационный блок / FAQ.

Причина вынесения в отдельный раздел — это один из наиболее частых вопросов пользователей домашних тестов.

Раздел должен:

- объяснять, что результат оценивается строго в интервале времени, указанном производителем;
- рекомендовать ориентироваться на официальную инструкцию;
- объяснять дальнейшие действия без постановки диагноза по фотографии;
- при необходимости рекомендовать консультацию медицинского специалиста.

Не заявлять диагноз только на основании внешнего вида фотографии теста.

# 15. Интерактив «Какой результат вы получили?»

Добавить три крупные кнопки:

- **Положительный**
- **Отрицательный**
- **Не могу понять**

После выбора раскрывается соответствующая информация.

## Положительный

Показать:

- что делать дальше;
- что домашний тест не заменяет медицинское подтверждение;
- когда обратиться к специалисту;
- блок тревожных симптомов.

## Отрицательный

Показать:

- когда может понадобиться повторное тестирование;
- необходимость учитывать инструкцию;
- что делать при сохраняющейся задержке.

## Не могу понять

Показать:

- примеры допустимых/недействительных результатов;
- ссылку на инструкцию;
- рекомендацию повторить тест при некорректном результате.

---

# 16. «Что делать дальше?»

## После положительного результата

Информационный алгоритм:

1. Ознакомиться с инструкцией и убедиться, что результат оценён корректно.
2. При необходимости подтвердить беременность медицинским методом по рекомендации врача.
3. Запланировать консультацию медицинского специалиста.
4. При боли, выраженном кровотечении, обмороке или других тревожных симптомах — обратиться за медицинской помощью без ожидания планового визита.

Не превращать этот раздел в назначение анализов или лечения без медицинских оснований.

## После отрицательного результата

Объяснить возможный следующий шаг:

- учитывать сроки тестирования;
- при необходимости повторить тест согласно инструкции;
- при сохраняющейся задержке обратиться к медицинскому специалисту.

# 31. Логика перехода на страницу покупки

Все ссылки покупки должны быть централизованы.

Пример:

```js
const products = [
  {
    id: "test-1",
    name: "Название теста",
    buyUrl: "#"
  }
];
```

Не прописывать URL страницы покупки десятки раз внутри компонентов.

При появлении точных URL отдельных товаров достаточно изменить их в одном источнике данных.

Внешнюю страницу рекомендуется открывать:

```html
target="_blank"
rel="noopener noreferrer"
```

# 35. Персонализированный пользовательский путь

В перспективе можно добавить первый вопрос:

## «Что происходит сейчас?»

Варианты:

- Хочу проверить беременность
- У меня задержка
- Я уже сделала тест
- Вижу слабую вторую полоску
- Тест отрицательный, но задержка есть
- Тест положительный

После выбора сайт автоматически прокручивает или перестраивает контент под сценарий.

Это желательно реализовать без обязательной регистрации пользователя.

---

# 36. Не реализовывать без отдельного согласования

Следующие функции не добавлять автоматически:

- ИИ-диагностика беременности;
- постановка диагноза по фотографии теста;
- загрузка медицинских документов;
- хранение чувствительных медицинских данных;
- персональные медицинские назначения;
- автоматическая интерпретация результата как окончательного диагноза;
- сбор лишних персональных данных.

# 37. UX-принципы

1. Пользователь за 5 секунд понимает назначение сайта.
2. За 1 действие может перейти к покупке.
3. За 1 действие может открыть инструкцию.
4. За 1 действие может перейти к интерпретации результата.
5. На странице нет информационной перегрузки.
6. Медицинские термины сопровождаются понятным объяснением.
7. На мобильной версии кнопки имеют достаточную touch-зону.
8. Не использовать манипулятивные CTA и искусственную срочность.
9. Не использовать неподтверждённые утверждения о точности или чувствительности.
10. Доверие важнее агрессивной продажи.

---

# 38. Референс Frautest

В качестве UX-референса можно использовать подход сайта Frautest:

- продуктовые страницы;
- визуальные пошаговые инструкции;
- видеоинструкции;
- визуальная интерпретация результата;
- FAQ;
- образовательные статьи;
- сервисы и калькуляторы вокруг женского здоровья;
- быстрый переход от информации о продукте к покупке.

Референс использовать только как источник идей по структуре UX.

Не копировать:

- дизайн;
- тексты;
- изображения;
- фирменную стилистику;
- уникальные элементы бренда Frautest.

Наш проект должен получить собственную визуальную идентичность на основе локального логотипа и упаковки.

# 39. Критерии готовности

Сайт можно считать готовым к первому запуску, когда:

- [ ] логотип корректно загружается из проекта;
- [ ] определена фирменная цветовая система;
- [ ] изображения продуктов используются без деформации;
- [ ] работает адаптивная версия;
- [ ] все основные CTA ведут на внешнюю страницу;
- [ ] каждый товар может иметь отдельную ссылку внешней страницы;
- [ ] инструкция соответствует файлам производителя;
- [ ] корректно отображаются варианты результата;
- [ ] присутствует FAQ;
- [ ] присутствует медицинский дисклеймер;
- [ ] PDF-инструкция открывается/скачивается;
- [ ] нет неподтверждённых медицинских характеристик;
- [ ] работают SEO metadata;
- [ ] настроены события кликов;
- [ ] мобильный sticky CTA не перекрывает контент;
- [ ] Lighthouse проверен;
- [ ] все внешние ссылки работают.

# 40. Главный пользовательский маршрут

```text
Главная
  ↓
Понимаю, какой это тест
  ↓
Выбираю свой сценарий
  ↓
Узнаю, когда тестироваться
  ↓
Смотрю, как провести тест
  ↓
Понимаю, как читать результат
  ↓
Получаю ответ «что делать дальше»
  ↓
Нажимаю «Купить»
  ↓
страница покупки
```

Главный принцип проекта:

> **Не просто продать тест, а дать пользователю понятный и безопасный путь от вопроса до следующего действия.**
